# Bundled Snapshot

Generated by `npm run data:refresh` from the upstream scholarly metadata API.
Upstream metadata is used under its open license.
This is an independent implementation, not Connected Papers data or its API.

The three DOI-queried examples cover Transformers, programmable CRISPR/Cas9,
and the first LIGO gravitational-wave observation. Each pool contains up to 300
real fetched work records with actual reference identifiers. Abstracts are
reconstructed from the source's inverted indexes, never generated. Missing
abstracts, venues, PDFs, authors, or references remain missing.
The upstream source currently resolves the Attention arXiv DOI to `W2626778328`
and returns `10.65215/2q58a426` as its canonical DOI and 2025 as its year,
whereas the
[authoritative arXiv abstract page](https://arxiv.org/abs/1706.03762) identifies
the seed DOI and first submission on 12 June 2017. This source
discrepancy is retained, not silently overwritten; the example remains 2025,
not a verified 2017 record. The original seed DOI remains an explicitly warned
offline alias, not an assertion that its returned canonical DOI is equal.

`integrity-audit.json` records independent live and authoritative HTML
observations from 2026-10-13. All four suspect records reproduce outside the
application/cache. HISTORIAE links to arXiv's RoBERTa record; AutoResearch links
to a different 2022 publisher record; the tutoring DOI identifies the publisher's
MizAR paper. These are source-consistency findings. They do not identify the
underlying cause, establish every citation as true or false, or authorize
relabeling a record. No alternative 2017 origin was verified in the bounded
lookup, so **no snapshot groups, metadata, IDs or rankings changed**.

Search, graph and paper responses expose seed conflicts in `meta.warning`,
including live, cached, stale-fallback and offline results. Existing persisted
responses are rechecked so old cache entries cannot hide the warning. Provenance
(`source` and `fetchedAt`) still describes acquisition, not scholarly verification.

The refresh is limited to 29 network requests, uses ID batches of at most 100,
and reuses persistent responses in `.cache/refresh`. A new refresh may use no
network calls while those responses remain fresh. The anonymous budget
is shared by IP and may be exhausted by other clients; a failed refresh leaves
the previous snapshot intact. Set `PAPERS_API_KEY` for a larger budget.
Seed validation requires the actual returned DOI, expected year and title,
both before collection and on the final origin record. A missing or conflicting
seed aborts publication and writes `refresh-anomalies.json` with returned records
and acquisitions, without replacing `snapshot.json` or `manifest.json`. There is
no title-only override or metadata repair. The existing Attention conflict means
a full refresh currently fails closed until a verified resolution exists.
Use `OFFLINE=1 npm run data:refresh` to validate against cached responses without
provider traffic; this reproduced the conflict and used zero network calls.

`manifest.json` records DOI seeds, exact query parameters, acquisition times,
response hashes, reported API credits, and the bundled snapshot's SHA-256.
The metadata source is mutable; reproduction means the same acquisition method,
not a promise of byte-identical records on a future date. Normalized records
retain the actual work IDs, references and metadata acquired by the script.
Audit observations are labeled projections, not original HTTP hashes;
the refresh-anomaly report separately preserves cached acquisition timestamps.

Sampling favors influential work. The candidate corpus is much smaller than
full scholarly indexes. Citation counts and coverage age; co-citation counts
are sample-local. An absent edge is not evidence that papers are unrelated.
Search in offline mode covers only this bundle and previously cached metadata,
ranked with typo-tolerant fuzzy matching over titles, authors, and topics.

## API

- `GET /api/health`: status, provider, offline mode.
- `GET /api/examples`: plain `Example[]`.
- `GET /api/search?q=...&page=1`: `SearchResponse`, 20 results per page; keywords, title, or DOI.
- `GET /api/graph?ids=W...[,W...]`: `GraphResponse`; one to three distinct IDs.
- `GET /api/paper/W...`: `{paper, meta}`.

`npm start` listens on `127.0.0.1:3001`; override with `HOST`/`PORT`.
Use `OFFLINE=1 npm start` for guaranteed no provider traffic. If `dist/index.html`
exists, Express serves the production SPA and route fallbacks. API errors remain
JSON and are never redirected to the SPA. Cache files are bounded, atomically
replaced, and contain no API keys. Rate limiting is process-local and ignores
untrusted forwarded IP headers; multi-instance deployments need a shared limit.
Limits are 60 API requests/minute/IP, 16 active API responses, two simultaneous
provider calls, 12-second provider timeouts and a 60-second API response deadline.
The runtime provider stops after 50 requests/day/process without a key (250 with
a key), and backs off after upstream failures. This is a conservative call cap,
not a guarantee against IP-shared quota exhaustion or a durable billing meter.
The cache holds at most 128 entries/24 MiB; older responses are evicted.
